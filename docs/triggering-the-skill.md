# 怎么触发 research-autonomy（以及怎么确认它真的跑了）

这份文档回答三个问题：

1. 想让它触发，我该怎么说？
2. 怎么确认它**真的**触发了，而不是敷衍我？
3. 哪些场合**不该**触发？

> **前置**：技能已经装好。
> - 只对一个工作区生效：`<工作区>\.dsh\skills\research-autonomy\SKILL.md`
> - 对所有工作区生效：`~\.dsh\skills\research-autonomy\SKILL.md`
>
> 技能就是**一个 markdown 文件**——没有代码、不注册任何工具。它改的是 agent 的**行为**；
> 真正"能查"的是随包安装的那些数据源插件（`dsh-free-search`、`@klarkxy/dsh-zhihu`、
> `dsh-wechat-mp-search`、`dsh-pubmed` 等）。两者的关系见第五节。

---

## 一、三种说法

### 1. 一句话（够用）

技能自己的触发清单里就写着它听得懂的词：

> **自己去查** · **自己学一下** · **搜一下** · **找资料** · **调研一下** · **学一下**

例：「这个我不太懂，**你自己去查**」「**调研一下** XXX」

### 2. 点名（最保险）

> **「用 research-autonomy 这个技能来做」**

技能名就是 `research-autonomy`。点名不会和别的技能抢。

### 3. 精确版（效果最好）

给它三件事：**任务 + 要一手来源 + 要它说明读了什么**。

> 「帮我调研 XXX。**要求**：一手来源优先，每个结论给链接，
> **说明你实际打开了哪几个页面**，查不到就说查不到。」

这句话把技能里最硬的两条规矩都点出来了：

- 铁律 3：**不许引用没打开过的链接**（搜索摘要只是线索，不是证据）
- 铁律 4：**不许编造**工具名 / 参数 / 配置键 / 字段 / 引用

## 二、怎么确认它真的跑了（三处痕迹）

技能自己规定了两处可见输出，加上一处副作用，一共三处：

### ① 开头先承认缺口

技能 Step 0 要求先写一行：

> **「要做这件事，我还缺：___」**

没有这一行，说明它直接开干了 —— 那就没走协议。

### ② 结尾必须有证据块

技能第 6 节规定的原文格式：

```
学到/用到的来源：
- <标题> — <url>   (primary)
- <标题> — <url>   (corroborates / contradicts)
置信度：high | medium | low — <为什么>
已保存：_knowledge\notes\2026-10-16-xxx.md
仍缺：<还不知道什么，什么能解开它>
```

### ③ 工作区里多出 `_knowledge\`

技能第 5 节规定的落档结构：

```
<工作区>\_knowledge\
  index.md                   每个笔记一行，让下次检索便宜
  raw\YYYY-MM-DD-<slug>.md   抓到的原文，逐字保留
  notes\YYYY-MM-DD-<slug>.md 缺口 / 发现 / 怎么用 / 影响 / 未知
  lessons\<topic>.md         去重后的长期结论（含"死路"）
```

**判断口径：**

| 你看到的 | 说明 |
| --- | --- |
| 结论 + 来源 + 置信度 + `_knowledge\` 里有东西 | **跑了** |
| 只有结论，没有来源和置信度 | **没跑** |
| 查了、也给了来源，但没落档 | **半跑**（"研究完不写下来"正是技能要消灭的反模式之一） |

## 三、哪些不该触发

技能第 1 节明确排除了这几种：

- 算术
- 格式化、改写**已经在上下文里**的文字
- **用户刚刚提供**的事实

这些触发了就是浪费钱。想明确关掉就说：

> **「这个不用查，直接用我给的信息做」**

技能规定这时必须**说明为什么没跑**（第 6 节末："If the protocol did not run, say why"），
所以正常回应是「这是你给的数值上的算术」之类，而不是沉默。

## 四、它不听话时，拿它自己的规矩压它

| 你怀疑 | 照着问 |
| --- | --- |
| 它在硬猜 | 「技能里写了不许编造工具名 / 参数 / 字段，你这些是从哪读到的？」 |
| 搜一次就下结论 | 「技能要求同一处最多 3 轮、且要换查询换引擎 —— 你换过没有？」 |
| 查不到却给了答案 | 「技能第 4 节：**别把『我找不到』变成『所以它大概是这样』**。你确认过吗？」 |
| 引用了一堆链接 | 「铁律 3：**没打开过的链接不许引用**。这几条哪些是你真的 fetch 过的？」 |
| 查完就完了 | 「第 5 节要求落档，`_knowledge\` 里有东西吗？」 |
| 一句话答完就跑了 | 「你的证据块呢？」 |

技能里最硬的一条，第 4 节原文：

> 同一处卡 **3 轮**之后要如实上报：已知什么、未知什么、需要什么。
> **一句诚实的「还缺 X，因为 Y」是好结果；一个自信的猜测不是。**

## 五、它和插件的关系（一句话）

- **技能**（1 个 markdown）：负责"**逼它去查**"
- **插件**（6 个，提供工具）：负责"**让它查得到**"

两边缺一不可：

| 只有技能 | 只有插件 | 两个都有 |
| --- | --- | --- |
| 它知道该查，但手上只有内置 `web_search` / `web_fetch` | 工具躺在列表里，它不一定想起来用 —— 这正是本技能要治的失败模式 | 有规矩，也有工具 |

能搜哪些地方、每个数据源当前是"实测 / 未测 / 被墙"，见 [capability-coverage.md](capability-coverage.md)。

## 六、想改它

技能就是一个 markdown，**直接编辑 `SKILL.md`** 即可 —— 改完新会话自动生效，**不需要重启**。

文件顶部的 frontmatter 决定它什么时候被想起：

```yaml
name: research-autonomy
description: ...   # 这行一直躺在 agent 的技能目录里，是匹配的依据
whenToUse: ...     # 触发场景，写得越具体越容易被想起
```

- 想让它**更爱触发**：把平时会说的说法补进 `whenToUse`
- 想让它**少管闲事**：把不该管的场景写进第 1 节的"不触发"清单

改完自己确认两件事：

1. frontmatter 里的 `name`（必须 kebab-case）和 `description` 还在 ——
   **这两个键写坏会让整个技能被静默丢弃**（官方有意的 fail-closed 设计），
   而表现只是"技能不见了"，很难查。
2. 新加的相对链接都指向真实文件。
