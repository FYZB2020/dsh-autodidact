## 1. Tier 0 — 必须在新会话跑（约 5 分钟，零额度）

> 前提：**新开一个会话**。老会话沿用启动时的插件版本，拿不到新工具（已验证）。

| # | 测什么 | 怎么做 | 通过标准 |
|---|---|---|---|
| T-01 | **工具是否真的加载** | 问：「列出你现在能调用的、名字里带 `zhihu` / `weixin` / `pubmed` / `deepread` 的工具」 | 至少出现：`zhihu_search`、`zhihu_global_search`、`zhihu_hot_list`、`zhihu_knowledge_search`、`weixin_search`、`get_weixin_article_content`、`deepread`、`pubmed_search_papers` |
| T-02 | **搜索提供方是否换源** | 打开 **设置 → 插件 → 插件配置 → 网页搜索** | 提供方不再是 `deepseek-official`（或能选到知乎/免 key 引擎） |
| T-03 | **技能是否被触发** | 给一个**没有现成材料**的小任务（例：「用我没给过你的某个库做 X」） | 它**先说出缺口**，再上网搜、读一手来源；不是直接凭印象写 |
| T-04 | **迭代行为** | 给一个第一次必然做不对的任务 | 失败后**回去改关键词重查**，不是原地重试或放弃 |
| T-05 | **失败不编造** | 临时断网，再问一个需要联网的事实 | 明确报「查不到/网络不可达」，**不编造** |
| T-06 | **留档习惯** | 跑完 T-03 后检查 `_knowledge\` | `notes\` 里新增带 `sources` 的笔记，`index.md` 多一行 |

**T-03 / T-04 / T-05 才是「这次改造成不成功」的真判据**，T-01/T-02 只是配置检查。

## 4. Tier 3 — 回归与边界（便宜但重要）

| # | 测什么 | 通过标准 |
|---|---|---|
| T-31 | **额度耗尽行为** | 人为用超某一池（如 `zhida` 100/天）后，报错应是 `Code=30002` 而不是静默失败 |
| T-32 | **风控行为** | 遇到 `Code=30003`（风控拒绝）时**不要立即重试**，应如实上报 |
| T-33 | **提供方冲突陷阱** | 若再装第二个搜索插件，`--dump-config` 后**`searchProvider` 与 `fetchProvider` 必须都设**（只设一个会让 `web_fetch` 彻底失效） |
| T-34 | **回退演练（⚠️ 有破坏性，先读懂再跑）** | `-Rollback` 会回退到**最近一次备份**——如果最近那次备份是装这批插件**之前**的状态，**真跑会把它们全删掉**。跑之前先看清备份目录的时间戳含义；只想起步撤销某一处配置改动的话，直接用你改之前备份的 `cordis.patch.yml.bak-*` 覆盖回去更精准。**建议第一次只做只读演练、不真跑** |
| T-35 | **不再触发历史坑** | 确认**没有**装 `dsh-web-search-metaso`（自定义事件类型会让历史会话打不开） |

## 6. 需要用户自己动手的（agent 做不了）

> **本节已按 2026-10-16 的实测结果修正**。

1. **确认插件装在「GUI 实际在跑的那个 profile」里** —— 本机 GUI 跑的是 **`desktop`**，
   不是 `web`。判定方法：查端口 19387 属主进程的命令行里的 profile 路径。
   **光「重启 + 新会话」不够** —— 装错 profile 时重启多少次都没用。
2. ~~去知乎初始化知识库~~ → **已过期**：知识库**已经存在**（今天创建的默认库）。
   上传仍报 `40006 file parsing failed`，**所以 40006 与「没初始化」无关**，
   是上传链路本身的问题（已记为待查项）。
3. ~~装 `yt-dlp` 和 `ffmpeg`~~ → **已装好并实测通过**：
   `yt-dlp 2026.08.19`、`ffmpeg/ffprobe 9.0.2`。
4. **视频转录前先确认 venv 里的 `av` 是 18.x** —— 插件没 pin 依赖，
   fresh venv 会装到 av 19.x 并**必然**抛
   `TypeError: open() got an unexpected keyword argument 'metadata_errors'`。
   本机已手工 pin 成 `av-18.1.0`；**换机器/重建 venv 要重做**：
   `uv pip install "av==18.1.0"`。
5. （可选）把 `@klarkxy/dsh-zhihu` 的 `dailyCallLimit` 从默认 100 调高 —— 你的实际额度是 5000/天。
6. （建议）**轮换知乎 Access Secret** —— 它已在聊天记录里出现过。
